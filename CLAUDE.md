# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Not a fork of Vane (https://github.com/ItzCrazyKns/Vane). A small toolkit around the official Docker image `itzcrazykns1337/vane`, pinned in `docker-compose.yml` to the digest the patches were verified against (Vane 1.12.2). No dependencies. See `README.md` for install and usage.

## Architecture

Pieces that run in different places:

- `cli/vane.mjs` runs on the host. Single-file Node 20+ ESM CLI (zero deps, `node:util` `parseArgs`). Flow: `GET {url}/api/providers`, resolve model names (exact key, exact name, unique substring, else OpenRouter slug), then `POST /api/search` (NDJSON when `--stream`). If Vane is unreachable it runs `docker start <container>` once and waits up to 90s. Exit codes: 0 ok, 1 runtime error (or no sources with `--require-sources`), 2 usage error (`UsageError` plus parseArgs codes). It only runs `main()` when executed, so tests can import its exports.
  - OpenRouter: Vane keeps custom models per provider (`POST/DELETE /api/providers/{id}/models` with `{type,key,name}`). The CLI finds the provider by name ("openrouter"), validates a slug against the public catalog `https://openrouter.ai/api/v1/models`, and registers it. `/api/config` is read only for the provider's `baseURL` (it also contains API keys: never log or keep them).
  - `--doctor` shells out to `docker`. It loads the patch definitions from `../patches` (`loadPatchDefinitions`) and checks every target in the container, so there is no second copy of any patch string.
  - A query that asks for an image or an article goes there without the flag: `autoRoute` parses the arguments again with `--image`/`--article`, so their option checks run (they only run when that flag is set).
  - `DEFAULTS` (URL, container, models, sources, mode) is exported and imported by `scripts/*.mjs`; do not re-read `VANE_*` env vars elsewhere.
- `cli/image/*.mjs` is image generation (`vane --image`), talking to OpenRouter directly, not to Vane. `catalogue.mjs`, `intent.mjs`, `policy.mjs`, `extract.mjs` and `present.mjs` are pure functions. `openrouter.mjs` is the only HTTP adapter, with `fetchImpl` injected. `download.mjs` guards provider image URLs (https, no private addresses, no IPv6 literals because they embed IPv4 in many forms and `new URL()` turns `[::ffff:127.0.0.1]` into `::ffff:7f00:1`, size cap, redirects re-checked). `isImageRequest` needs the image noun followed by the end, punctuation or a word like of/showing/for/that ("an image classifier", "a drawing app" are not requests); `isImageEdit` refuses questions (a trailing `?`, "in which …") and lets give/use/try/"make a …" count only with a word pointing at the picture (it, this, image, version, style, background …). `generate.mjs` is the pipeline; its dependencies are injected and failures are returned as values. `save.mjs` writes files. Pure generators (output modality `image` only) must use `POST /api/v1/images`; chat completions answers 404 for them. Tests in `cli/test/image.test.mjs` use a fake client; real runs need OpenRouter credits.
- `patches/patch-*.js` are CommonJS scripts that run inside the container as root and string-replace exact fragments of Vane's minified `.next/server/...` bundles. Each one only declares `TARGETS` (exported) and calls `run()` from `patches/lib/apply-targets.js`, the one patch engine: it checks every target first and changes nothing on a mismatch (exit 1), refuses a bundle that does not parse (`vm.Script`), writes `*.bak`, and is idempotent. A target is `{name, file, from, to}` or `{name, file, alts:[{from,to}]}`, plus `marker` and `optional`. `patches/lib/vane.js` holds what several patches share: the bundle paths (`FILES`), Vane's scrape-failure title, and the `RANK_ON_ORIGINAL_TEXT` target used by two patches. Patches run in file-name order and later ones edit earlier ones' output. When that happens, give the earlier target a `marker` (a substring the later patch leaves alone), or re-running the earlier patch fails with "found 0"; the skip check is "`to` or `marker` present". A `to` must never be a substring of its `from`; use a `/*fane:...*/` marker when a fix only deletes code. `cli/test/patches.test.mjs` checks every declared target's shape. Injected functions (`ENRICH`, `SOCIAL`, `RANK`, `STRIP`) are exported and imported by their tests. CI runs two full passes in file order; `scripts/apply.mjs` copies the whole `patches/` folder (patches need `lib/`). `patch-new-chat` fixes Home/"+" showing the previous chat (Vane's ChatProvider resets only on a *different chat id*; the patch resets when `location.pathname` is `/` with messages on screen, checked every render because Vane's `useParams` does not follow `history.replaceState` and its `next/navigation` import has no `usePathname`). `patch-ui-fane-link` adds a nav item (`FANE_PAGE_URL`, opens in a new tab) to the same chunk's `p` array that feeds both the sidebar and the phone bar; its icon is inserted in front of `fane_theme`, so it must run after `patch-theme-toggle` (inserting before `y=` would split the toggle's own text and the doctor would report it missing). `patch-theme-toggle` also turns Vane's settings gear (a plain `div` with an onClick) into a labelled keyboard button, and edits a browser chunk (`FILES.layoutClient` under `/home/vane/public/_next/static`, served with `max-age=0`, so a normal reload picks it up); there `a` is webpack's require and module `70460` is next-themes. The minified names (`c.classification.skipSearch`, `g.A()`) are build-specific; on a new Vane build the fragments must be re-derived. Inside the speed/balanced block of module 40824 the module imports `f`, `g` and `h` are shadowed by locals, so it captures them as `FANE_*` module-level names; in the quality block `e` is shadowed too. Inside minified callbacks, watch for shadowed single-letter names (e.g. `b` is both the research config and a `forEach` index).
- `searxng/settings.yml` ends up at `/etc/searxng/settings.yml` in the container. Its `secret_key` is a placeholder that is replaced with a random value at install time, never in the repo file. Installers replace the whole `secret_key:` line, so the placeholder text appears only in that file.
  - The `core.ac.uk` engine block (`api_key: ''`, `inactive: true`) gets `CORE_API_KEY` and `inactive: false` at install time. Two places do this, and a change to one goes in the other: `scripts/searxng-settings.mjs` `renderSettings` (used by `apply.mjs`, which compares the rendered file, so a new or removed key re-applies and restarts) and the sed in `docker/fane-entrypoint.sh`. A test runs that sed against `renderSettings`.
  - A key outside `[A-Za-z0-9._-]` is refused, so it cannot break the YAML line or the sed. Never print the key.
  - Without a key SearXNG does not load the engine and drops its name from Vane's engine list, so `patch-scholarly-sources` can always name it.
  - CORE results carry the whole paper text as `content`, so the same patch cuts result text to `LONG_RESULT_CHARS` before Vane embeds it or the writer sees it. That clip is a statement of its own, so `patch-social-sources`' `c=(b.results||[]).map(` anchor is untouched.
  - The `academic engines` target has a second `alts` entry that upgrades a container patched before CORE was added.
- `patches/patch-image-chat.js` hooks Vane's chat route (web UI): it `import()`s `cli/image/vane-hook.mjs` from `FANE_IMAGE_DIR` at runtime, so the UI and `vane --image` run one image pipeline. If the hook is missing or throws, Vane answers as usual. `scripts/apply.mjs` copies `cli/image` there (by hash) and restarts, because Node caches imported modules; Compose mounts it. `store.mjs` writes each image to `<data dir>/fane-images/<sha256>.<ext>` (`storeDirFor(configPath)`; `patches/lib/vane.js` `IMAGE_STORE_DIR` must equal it, a test checks) and `patch-image-serve` adds a GET to Vane's `/api/uploads` route (Vane does not serve files added to `public/` after boot) that calls `serveImage`; the answer then holds a link (~1 KB) instead of base64, and an image that cannot be stored is embedded. Every answer the hook writes ends with `ANSWER_MARKER` (`tagged()`, an invisible HTML comment; `patches/lib/vane.js` `IMAGE_ANSWER_MARKER` must equal it, a test checks) and `patch-image-ui` edits the browser message chunk (`FILES.messageClient`) so the side column with Vane's Search images/videos buttons is left out when the answer text contains it; the variable `b` there also gates the answer body and its action row, so only the side column's own use of `b` is patched. `present.mjs` turns a result into the web UI answer (`renderResult`): a raw-HTML 2x2 grid (Vane renders raw HTML and keeps `data:image` URLs but drops `width`/`min-width` from inline styles, so the width is the `width="100%"` attribute; it also trims the space at the edge of a span (use a margin) and shows `&#39;` literally (apostrophes are not escaped; one inside a word becomes ’), and its prose styles give `img` a 2em margin and `code` a small bold type, so the img sets `display:block;margin:0` and the code `font-size:inherit;font-weight:400`), catalogue model names, a cost and time line (everything Fane adds around the answer is small, dimmed with `opacity` so both themes work, regular or medium weight, never italic or quoted; status, summary and notes are one `quiet()` block; the price is `≈`, numbers and units use no-break spaces; a caption sits 6px under its image and rows are 20px apart; accessibility: `quiet()` is `role="status"`, the alt text names the image but not the model (the caption does), the full-size link has a title, and Vane does not decode entities in attributes so `attr()` writes alt text with curly quotes and look-alikes instead of `&quot;`), and `explainFailure` (policy.mjs) for failures. `generate({onProgress})` reports each landed image (`{ready, total, slot, model, name, image}`; a throwing listener is ignored); the hook stores it at once (`store.put`) and shows it with `renderProgress`, in a queue so updates stay ordered. Stored images are links, which is why they can be shown in progress (every `update()` re-sends the whole answer; an embedded image would be megabytes). Follow-up edits: `isImageEdit` + `pickReferenceIndex` (intent.mjs) and `storedUrlsIn`/`store.get` (store.mjs); the hook finds the earlier images in the previous answer's text and generates with them as `references` (`enhance: false`). Vane's browser keeps the progress text as the earlier answer until a reload, so the patch passes `lastAnswer()` (reads the previous message's text blocks from Vane's DB via drizzle, `i.A`/`j.messages`) and the hook only falls back to the browser's `history`. The chat patch has upgrade targets (`mode`, `history`, `lastAnswer`) that each add one parameter to an already-patched hook; their markers keep later versions from re-matching. `parseImageOptions` (intent.mjs) reads count and shape from the prompt for both the hook and the CLI (flags win; `--aspect` has no parseArgs default so the CLI can tell). Everything from a prompt or model is `escapeHtml`'d and only `data:image/...;base64,` URLs reach HTML. Vane builds follow-up chat history from the answer's text blocks, so embedded images are sent back with every follow-up. `findOpenRouterKey()` (adapter) is the one place that picks the OpenRouter key from Vane's provider list, for both the CLI and the hook.
- `cli/write/*.mjs` is article writing (`vane --article`; also chosen automatically by `isArticleRequest`), ported from reasoner's article method (ARTICLE_METHOD_SPECIFICATION.md). Same rules as `cli/image`: pure modules, `pipeline.mjs` has its dependencies injected (`client` = the OpenRouter adapter, `retrieve` = Vane's `search()`), failures are values. `language.mjs` (script detection, per-language stock-phrase lists, Greek homoglyph/typography checks, `repairFinalNu` for the dropped final ν of «την/στην/μην», which the pipeline and the editor apply with the homoglyph repair; the Greek list is native Greek, matched on `fold()`ed text: no accents, final sigma as sigma), `intent.mjs` (needs a writing verb at the start, Greek and English; a bare "κείμενο" is not enough), `checks.mjs` (deterministic checks and `renumber`/`sourcesSection`: the model cites `[n]`, `[1, 4]` or a range `[2–4]`, code renumbers by first appearance and writes the sources list, so it cannot invent a URL; the pipeline and the editor give `runChecks` all sources when the article cites none, or the citation check was skipped and an unsourced article passed clean; the numbers check skips sources without text, i.e. an article read back for an edit), `gate.mjs` (audit floors and weights, claim ledger), `models.mjs` (`PHASES` per Vane mode, `tokensFor`: Greek takes ~2.4x the tokens; every role has an explicit budget because reasoner found phases silently capped at 2048), `llm.mjs` (one role call over a model chain; rejects `finish_reason: length`, empty, `<think>`/"Thinking Process" and non-JSON; 401/402 stop the run; after a network failure, no HTTP status and not a timeout, the next model waits `NETWORK_WAIT_MS` times the number of failures in a row, because two live Quality runs lost the connection and spent every chain in seconds), `prompts.mjs` (sources are marked untrusted; the human-voice rules are in the draft prompt, in Greek for Greek). Edited text replaces the article only if `refuse()` finds it plausible (not much shorter, title and citations kept). Length is held in two ways: every editing prompt (`revise`, `polish`, `style`, `copy`) carries `lengthRule` (current words, target, hard cap +10%), and `trim()` in the pipeline cuts a text back with a `rewrite` call whenever it is more than `MAX_OVER` (1.25) times the target, after the draft and after each accepted edit, and again (`TRIM_PASSES` = 2 calls at most) while it is over `LENGTH_CAP` (1.1, the cap `lengthRule` states); the instruction names the words to remove, because "cut it to about N" alone went from 785 to 651 for 500. A trim that is not shorter, loses the title or fails keeps the longer text and lands in `degraded`. An editor's token budget is sized on the longer of the target and the article it gets back. `THINKING_HEADROOM` is 8000 (a Quality copy edit was cut off at 4975). Costs: `llm.mjs` `costOf` takes `usage.cost`, else estimates from token counts and `prices` (USD per million, from `selectChains`), because some models (minimax-m3.1-flash, grok-4.7) report none and the edit on Speed showed no cost. Found in a live Quality run: draft 543 words, revise 813, the audit retry's revise 899 for a target of 500 (`vane --article` prints the words after each phase). Default chains come from `catalogue.mjs` `selectChains`: only models with a passing entry in `cli/write/trial.json` (written by `scripts/article-trial.mjs`: a 150-word article in English and Greek with the real draft prompt, and a JSON answer, judged by `judgeTrialDraft`/`judgeTrialJson`) are eligible; the mode picks a price tercile of those, roles take primaries round the band so neighbours differ in lab, fallbacks come from the same band first. Every call sends `reasoning: { effort: 'low' }` (`REASONING`): without it thinking models burned the whole budget and returned empty text. Redo the trial when the catalogue changes (about $1); `vane --list-article-models` shows the result. Web UI: `patch-article-chat` inserts `cli/write/vane-hook.mjs` `handleArticleRequest` before Vane's classification step (next to the image hook; each leaves its own marker and either order works; `FANE_WRITE_DIR` is mounted by Compose or copied by `apply.mjs`, which now syncs `cli/image` and `cli/write` incl. `trial.json`). It passes `research(q)`, which runs Vane's own classifier and research class (`e.L`, `f.A`) on the chat's model and mode, so the user sees Vane's research panels and no second search stack is needed; `researchDone` emits `researchComplete`. Rules learned in the live check: Vane renders every `[n]` as a chip for its *own* source list, so the web answer writes citations as superscript links (`linkCitations`: `[¹](url)`), the CLI keeps `[n]`; `present.mjs` strips HTML tags from model text (Vane renders raw HTML); each non-English research is a full Vane research with its own panel, so only one English query is added (`EXTRA_QUERIES`); thinking models used up the first token budgets even at low effort (an outline cut off at 3880 tokens by three models in a row), so `tokensFor` adds `THINKING_HEADROOM`. A `ui()` test helper must not spread a `log` key into hook options (the hook's own `log` option). The article language comes from the whole request, not the topic («γράψε ένα άρθρο για το iPhone 17» has a mostly Latin topic). `cleanMarkdown` strips tags until nothing changes (one pass rebuilt `<<img …>img onerror=…>` into a tag). Follow-up edits (`edit.mjs`): `isArticleEdit` (a leading edit verb, EN and Greek; never a question: `?`, or `;` in Greek text, nor thanks or praise; the hook also needs a sources list in the earlier answer, as `--edit-article` does, because Vane's own answers have a "# " title too), `parseArticleAnswer` (reads the previous answer back: superscript links to `[n]`, the "Sources" list to `{title,url}`, status paragraph and marker stripped; null unless it has a title and 80+ words), `targetLanguage` (a translation request that ends the sentence), `createArticleEditor` (one `rewrite` call on the `draft` chain, refuses a lost title or under a quarter of the text, then renumber, sources list and checks as for a new article; when `needsNewFacts` matches ("add", "expand", «πρόσθεσε») and a `retrieve` is given, one research runs first and up to `MAX_NEW_SOURCES` new pages are appended after the old sources, with excerpts, and the prompt allows facts from them). `vane --edit-article <file> "<change>"` runs the same editor on a file from `--article` (Vane is started only when the change needs research). Web answers write the sources list as `<a href>` lines (`sourcesSection(..., { html: true })`), because Vane's browser code replaces every `[x]` of an answer with sources by `x.split(",")` pieces (numbers become citation chips, the rest `[piece]`), which broke titles with commas; `parseArticleAnswer` reads both forms back. The image hook's edits get a vision check (`keepsReference` in `generate.mjs`: the text model sees the original and the result, "no" rejects it and the chain moves on), because fallbacks listed as taking image input drew new pictures. `judgeTrialDraft` returns a `score` (stock phrases, numbers in no source, uncited share, length miss, flat rhythm, Greek typography) that `selectChains` ranks by, falling back to `tellsPerThousand` for an old trial.json. The hook gets `lastAnswer`/`history` from the chat patch (`LAST_ANSWER` is exported by `patch-image-chat.js`; the second target of `patch-article-chat` upgrades a hook installed without them) and checks `isImageRequest` first, so "make an image ..." after an article stays an image request. `runArticle` in `vane.mjs` routes `-o`/`--tier` to the phases (`MODE_FOR_TIER` inverts `TIER_FOR_MODE`).
- Single source of truth: OpenRouter's address is `OPENROUTER_BASE_URL` in `cli/image/openrouter.mjs`, and the CLI's catalogue calls go through that adapter too. Chat versus Image API is decided by `viaOf()` in `cli/image/catalogue.mjs`. A tier is a price band (cheapest/middle/dearest third of the family, disjoint), `selectModels` fills the primaries from the tier's own band before borrowing from neighbouring bands, and `TIER_FOR_MODE` maps Vane's Speed/Balanced/Quality to budget/value/premium (the chat patch passes `mode:b.config.mode` to the hook; the CLI keeps `--tier`, default value). Image option lists (`FAMILIES`, `TIERS`, `VIAS`, `ASPECT_RATIOS`, `IMAGE_SIZES`) are defined once and imported by the CLI for validation and help text. The pinned Vane digest lives only in `docker-compose.yml`; CI greps it from there. Accepted duplication: SearXNG engines named in a patch must also be enabled in `settings.yml`, since they are two layers, and a comment in each points to the other. The README option table restates `vane --help`.
- Two ways to install the patches and settings, both must keep working:
  - Both publish Vane's port on 127.0.0.1 only: Vane has no login and `GET /api/config` returns the provider API keys. So the CLI's default URL is `http://127.0.0.1:3000`, not `localhost`: Node and browsers try `::1` first, and another dev server listening on `[::1]:3000` then gets every call.
  - `docker-compose.yml` + `docker/fane-entrypoint.sh`: the script runs as the container entrypoint on every start (patches, render settings with a random key, then `exec docker-entrypoint.sh`). A failing patch warns and Vane starts unpatched.
  - `scripts/apply.mjs`: the same for an existing `docker run` container (idempotent, restarts only on change, then runs `--doctor`).
- `docs/` is the project page (GitHub Pages from `/docs`): static `index.html`, `style.css`, `page.js` and 12 real pictures from `vane --image` (one prompt through the three tiers; `docs/img/*.jpg` resized from the originals, which stay local in the gitignored `.taste-skill/`). Built with the taste skill (direction "type and nothing else"); `inspect.mjs` from that skill is the check (0 FAIL; the no-video WARN is defended: no honest clip exists). The page's numbers (model names, prices, 1.8/6.5/38 cents) are from those runs and are hardcoded in `page.js`; redo the runs to change them. The name is real text sized to the width (Bricolage Grotesque 600 at -0.04em is 1.899em wide).
- `scripts/engine-check.mjs` queries each SearXNG engine once from inside the container.
- `scripts/article-bench.mjs` is how to tell whether an article change helps. It runs `bench/articles.json` through the CLI (`--article --json`, the key passed to the child in `OPENROUTER_API_KEY`). A fixed judge model then grades each final article with `prompts.factcheck` and `prompts.audit` (`judgeArticle`). Compare the judge's numbers, not the pipeline's own (`selfSupport`/`selfAudit`): those come from the prompts being tuned and from a fact-check of the draft. The default judge is `openai/gpt-6.1-terra-pro`, because `claude-sonnet-5.5` leads the Quality audit chain. Pick a judge outside the chains of the mode you benchmark; rows written partly by the judge are marked `selfJudged`. It reuses `aggregate`, `median` and `runCli` from `scripts/bench.mjs`.
- CI (`.github/workflows/ci.yml`) runs the unit tests, applies each patch twice inside the pinned image, and runs `node --check` on every bundle that has a `.bak`, server and browser (so every patch must write one). Changing the digest in `docker-compose.yml` must go with patch updates that keep this job green.

## Commands

```bash
npm test --prefix cli                # node --test, cli/test/*.test.mjs (pure functions only; no Docker or Vane needed)
node --test --test-name-pattern="resolveModel" cli/test/vane.test.mjs   # tests by name
npm install -g ./cli                 # installs the `vane` bin (links to the repo)
vane --doctor                        # full health check, exit 1 on a failure
node scripts/apply.mjs               # (re)apply patches + SearXNG settings to a running `vane` container
docker compose up -d                 # alternative: patched Vane from the pinned digest
node scripts/engine-check.mjs [--engines a,b]
node scripts/bench.mjs -m claude-haiku-5-5 --modes speed,balanced --baseline bench/baseline.json   # real queries; measure a change before/after
node scripts/article-bench.mjs --key-from-vane [--only id,id] [--baseline file]   # paid: bench/articles.json through vane --article, graded by a fixed --judge; measure article changes with it
vane "q" --verify                    # lexical citation check (verifyCitations in cli/vane.mjs, threshold 0.3)
```

## Environment gotchas (Windows)

- The CLI default model `google/gemini-3.8-flash` is registered automatically only if the Vane OpenRouter provider exists. Otherwise pass `-m` or set `VANE_CHAT_MODEL` after checking `vane --list-models`.
- The Vane provider called "Openrouter Fane" on the dev machine is an OpenAI-type provider whose Base URL is `https://api.openai.com/v1`, so OpenRouter models time out. `vane --doctor` warns about this; fixing it means entering an OpenRouter key in Vane's UI (do not do that for the user).
- In Git Bash, `export MSYS_NO_PATHCONV=1` before ad-hoc `docker exec ... /path` commands, or paths get rewritten. Files passed to `docker cp` must be somewhere `docker.exe` can see (not `mktemp` paths). The Node scripts use `execFile` and do not have this problem.
- In PowerShell, `npm` fails with an execution-policy error; use `npm.cmd` or Git Bash.
- Vane's research step sometimes returns zero sources for a query that worked a minute earlier; use `--require-sources` when that matters.
- Brave, DuckDuckGo and Startpage are blocked from the dev machine's IP (CAPTCHA or rate limit, also through a VPN). Bing and Yandex work intermittently. Do not try to bypass the CAPTCHAs; restart the container to clear SearXNG's suspension timers after changing network.
- `docker/*.sh` must stay LF (`.gitattributes` enforces it); CRLF breaks the container entrypoint.
